# MOBI.AI 디자인 규칙

현대자동차 공모전 프로젝트다. 세 가지를 합쳐 우리만의 규칙으로 쓴다.

| 영역 | 기준 | 출처 |
| --- | --- | --- |
| 색·비율·간격 | 현대자동차 브랜드 | 현대자동차 마이현대 소개 페이지의 실제 스타일 실측 (2026-11-08) |
| UX 행동·화면 구성·문구 | 토스식 원칙 | 「토스에서 찾아본 10가지 UX 법칙」(모비인사이드 재게시, 2023) — 외부 기획자의 관찰 글이며 토스 공식 가이드가 아니다 |
| 반응형 | 필수 | 이 프로젝트 규칙 |

**토큰은 `src/app/globals.css` 에 있다.** 컴포넌트에서 색·크기를 직접 정하지 말고 토큰 클래스만 쓴다. 임의 색상(`bg-[#...]`, `rgb(...)`, 인라인 `style={{ color: "#..." }}`)은 ESLint 에러다.

## 1. 반응형 (필수)

1. **모바일 우선으로 작성한다.** 접두어 없는 클래스 = 모바일(360px~), `md:` = 태블릿(768px~), `lg:` = 데스크톱(1024px~), `xl:` = 넓은 화면(1280px~). 현대 사이트와 같은 768/1024 기준이다.
2. **360 · 390 · 768 · 1024 · 1440px 에서 모두 깨지지 않아야 한다.** 가로 스크롤이 생기면 안 된다.
3. **좌우 여백**: 모바일 `px-5`(20px) → `md:px-6`(24px) → `lg:px-7.5`(30px).
4. **본문 폭**: `max-w-content`(1120px) 가운데 정렬. 폼·결과처럼 한 가지 작업만 하는 화면은 `max-w-narrow`(560px). 갤러리·대시보드만 `max-w-wide`(1400px).
5. **열 배치**: 모바일은 1열 세로 배치가 기본이다. 카드 목록은 모바일 1열 → `md:` 2열 → `lg:` 3~4열.
6. **헤더 높이**: 모바일 `h-14`(56px) → `md:h-16`(64px) → `lg:h-20`(80px). 모바일에서는 탭·메뉴를 드롭다운이나 전체 화면 메뉴로 접는다.
7. **터치 대상은 최소 44×44px, 대상 사이 간격은 최소 8px.** 주요 버튼은 52px(`h-13`).
8. **hover 에 기능을 걸지 않는다.** hover 는 꾸밈만 하고, 같은 기능은 클릭·포커스로도 되어야 한다. (Tailwind v4 의 `hover:` 는 마우스가 있는 기기에서만 적용된다)
9. **전체 높이는 `min-h-dvh`** 를 쓴다 (`100vh` 는 모바일 주소창 때문에 넘친다).
10. **하단 고정 버튼은 safe-area 를 더한다**: `pb-[calc(env(safe-area-inset-bottom)+16px)]`. (루트 layout 의 `viewportFit: "cover"` 가 전제)
11. **이미지는 `next/image` + `sizes` + 고정 비율 컨테이너**로 넣어 레이아웃이 밀리지 않게 한다 (4장 비율 참고).
12. **표는 모바일에서 카드 목록으로 바꾼다.** 가로 스크롤 표는 마지막 수단이다.
13. **확대를 막지 않는다** (`maximumScale`, `userScalable: false` 금지).

## 2. 토스식 UX 원칙 → 우리 규칙

| 원칙 | 우리 규칙 |
| --- | --- |
| **익숙함** (사용자는 다른 서비스에서 배운 방식으로 이해한다) | 헤더·탭·하단 CTA·뒤로가기 위치는 일반적인 모바일 앱 관례를 따른다. 새로운 조작 방식을 발명하지 않는다. |
| **한 화면에 한 가지** ("1 thing / 1 page") | 한 화면은 하나의 목적만 가진다. 입력이 여러 단계면 단계별 화면으로 나누고 진행 표시를 둔다. **주 CTA는 화면당 1개.** |
| **선택지는 적게, 목적별로 묶기** | 같은 목적의 요소를 한 섹션으로 묶고 섹션 제목을 단다. 첫 화면의 선택지는 최대한 줄이고 나머지는 "더보기"로 넘긴다. |
| **덩어리로 보여주기** (기억은 7±2 덩어리) | 한 섹션의 항목은 7개 이하. 숫자는 끊어 읽게 표시한다 (전화번호 `010-1234-5678`, 차량번호, 금액 천 단위 쉼표). |
| **입력은 적게, 받을 때는 너그럽게** | 꼭 필요한 정보만 묻는다. 하이픈·공백 유무 등 여러 형식을 받아 내부에서 정리하고, 입력 중 자동 서식을 적용한다. |
| **복잡함은 서비스가 떠안기** | 사용자가 고르기 전에 추론할 수 있으면 미리 채우거나 추천한다 (예: 입력값으로 차종·지점 추천, 최근 선택값 기본 선택). |
| **마지막 인상이 기억된다** (특히 실패) | 실패·빈 화면은 하나의 공용 컴포넌트로 통일한다. 탓하지 않는 해요체 문구 + 바로 할 수 있는 다음 행동 1개. 같은 실패는 어디서나 같은 화면이어야 한다. |
| **보기 좋으면 쓰기 쉽다고 느낀다** | 넉넉한 여백, 정돈된 정렬, 적은 색 수. 장식보다 여백으로 구분한다. |
| **강조는 드물게** (다른 것만 기억된다) | 강조색(`highlight`)·배지·애니메이션은 화면당 한 곳에만. 신규 기능·알림 같은 꼭 알려야 할 것에만 쓴다. |
| **0.4초 안에 반응** | 모든 조작은 즉시 눈에 보이는 반응을 준다 (눌림 상태, 낙관적 업데이트). 0.4초 넘게 걸리는 로딩은 스켈레톤, 외부 조회처럼 긴 작업은 진행 안내 애니메이션을 보여준다. |

## 3. 색 (현대자동차 기반)

| 토큰 | 값 | 용도 | 금지 |
| --- | --- | --- | --- |
| `primary` | #002C5F (Hyundai Blue) | 주 CTA 배경, 활성 탭·선택 상태, 로고 영역 | 넓은 배경 면 |
| `primary-strong` | #001B3A | 주 CTA hover·눌림 | — |
| `accent` | #007FA8 (Active Blue) | 텍스트 링크, 보조 강조, 포커스 링 | 큰 면적 |
| `highlight` | #00AAD2 (Sky Blue) | 배지·장식 배경, 플로팅 도움 버튼 | **글자색, 흰 글자를 얹는 버튼** (대비 부족) |
| `sand` | #E4DCD3 | 브랜드 영역 배경(상단 비주얼), 구분 | 본문 영역 전체 |
| `sand-light` | #F6F3F2 | 섹션·카드 배경, 정보 박스 | — |
| `ink` | #000000 | 제목·본문 | — |
| `ink-secondary` | #444444 | 보조 본문 | — |
| `ink-tertiary` | #666666 | 설명·캡션 | 이보다 옅은 색으로 정보 전달 금지 |
| `ink-disabled` | #999999 | 비활성·placeholder | **본문·정보 텍스트** (대비 2.8:1) |
| `surface` | #FFFFFF | 기본 배경, 주 CTA 위 글자 | — |
| `surface-dark` | #1C1B1B | 푸터·다크 섹션 | — |
| `surface-tab` | #444444 | 탭 바 배경 (활성 탭은 `surface` + `ink`) | — |
| `line` | #E5E5E5 | 구분선·입력 테두리·카드 테두리 | — |
| `danger` / `success` / `warning` | #D32F2F / #2E7D32 / #B26A00 | 상태 표시 (현대 페이지에 없어 프로젝트에서 정의) | 장식 |

- **화면 색 비율**: 흰색·`sand-light` 바탕이 대부분, 글자는 `ink` 계열, `primary` 는 CTA·활성 상태처럼 작은 면적에만. 현대 페이지도 흰색·밝은 샌드가 대부분이고 브랜드 블루는 포인트로만 쓴다.
- 대비: 본문 4.5:1 이상 (WCAG AA). `ink-tertiary`(#666) 가 흰 바탕에서 쓸 수 있는 가장 옅은 정보 텍스트다.
- 다크 모드는 현재 범위 밖이다 (`color-scheme: light`). 도입하려면 사용자와 먼저 상의한다.

## 4. 비율·간격·레이아웃 (현대자동차 기반)

| 항목 | 값 |
| --- | --- |
| 브레이크포인트 | 768px(`md`), 1024px(`lg`) |
| 좌우 여백 | 20px → 24px → 30px |
| 본문 폭 | narrow 560px / content 1120px / wide 1400px |
| 헤더 높이 | 56px → 64px → 80px |
| 섹션 세로 간격 | 모바일 48px(`py-12`), 태블릿 64px(`md:py-16`), 데스크톱 80px(`lg:py-20`) |
| 간격 단위 | 4px 배수 (Tailwind 기본 spacing). 요소 사이 최소 8px |
| 상단 배너 이미지 | 데스크톱 16:3 (`aspect-[16/3]`, 현대 1920×360), 모바일 4:3 (`aspect-[4/3]`) |
| 콘텐츠·기능 카드 이미지 | 14:17 세로형 (`aspect-[14/17]`, 현대 560×680) |
| 차량·썸네일 이미지 | 16:9 (`aspect-video`) |
| 모서리 | 구조 요소(섹션·배너·탭 바)는 각지게(0). 조작 요소(버튼·입력·카드)는 `rounded-control`(8px). 칩·배지는 `rounded-full`. 바텀시트 윗모서리는 `rounded-t-sheet`(20px) |

현대는 거의 모든 모서리가 각진(0px) 디자인이고, 토스는 둥근 디자인이다. 그래서 큰 면은 현대처럼 각지게, 손으로 누르는 요소만 토스처럼 살짝 둥글게 섞는다.

## 5. 타이포그래피

글꼴: `font-sans` (Pretendard → Apple SD Gothic Neo → Noto Sans KR → 맑은 고딕). 현대 전용 서체(Hyundai Sans)는 공모전 측이 제공·허용한 경우에만 쓴다.

| 토큰 (모바일 → `lg:`) | 크기 | 용도 |
| --- | --- | --- |
| `text-display` → `lg:text-display-lg` | 32 → 56px | 첫 화면 대표 문구 (페이지당 1개) |
| `text-title` → `lg:text-title-lg` | 28 → 44px | 페이지 제목 (h1) |
| `text-heading` → `lg:text-heading-lg` | 22 → 30px | 섹션 제목 (h2) |
| `text-subheading` → `lg:text-subheading-lg` | 18 → 20px | 소제목·카드 제목 (h3) |
| `text-body-lg` | 17px | 강조 본문, 주 CTA 글자 |
| `text-body` | 16px | 기본 본문 (줄간격 1.7) |
| `text-body-sm` | 15px | 목록 보조 정보 |
| `text-caption` | 13px | 캡션·도움말 |
| `text-micro` | 12px | 법적 고지 등 최소 크기 (이보다 작게 쓰지 않는다) |

- 굵기: 제목 `font-bold`, 본문 `font-normal`, 강조 `font-medium`/`font-bold`. 한 화면에 굵기 3단계 이하.
- 한국어 줄바꿈은 `word-break: keep-all` (전역 적용). 문장 중간에 `<br>` 로 강제 줄바꿈하지 않는다.
- 숫자 비교가 필요한 표·금액은 `tabular-nums`.

## 6. 컴포넌트 규칙

- **주 CTA 버튼**: `h-13 rounded-control bg-primary px-5 text-body-lg font-bold text-surface hover:bg-primary-strong`. 모바일은 `w-full`, `md:` 부터 `w-auto md:min-w-60`. 동사형 문구("예약하기", "다음"). 처리 중에는 비활성 + 로딩 표시로 중복 클릭을 막는다.
- **보조 버튼**: `bg-sand-light text-ink` 또는 `border border-line bg-surface text-ink`. 주 CTA보다 눈에 띄면 안 된다.
- **텍스트 링크**: `text-accent underline-offset-4 hover:underline`.
- **모바일 하단 고정 CTA**: 한 가지 작업 화면(폼·결제·예약)의 주 버튼은 모바일에서 하단 고정 + safe-area 여백. 본문 끝에 버튼 높이만큼 여백을 둬서 가리지 않게 한다.
- **입력**: 라벨은 입력칸 위(placeholder로 라벨 대신 금지), 높이 `h-13`, `rounded-control border border-line`, 포커스 시 `border-primary`. 오류는 입력칸 아래 `text-caption text-danger` 로 이유와 고치는 방법을 함께. 숫자 입력은 `inputMode="numeric"`, 자동 서식 적용.
- **목록**: 모바일은 세로 목록, 행 높이 최소 56px, 구분선 `border-line`. 섹션당 7개 이하, 넘치면 "더보기".
- **카드**: `rounded-control bg-sand-light` 또는 `border border-line`. 그림자는 쓰지 않거나 아주 약하게.
- **탭**: 데스크톱은 현대식 탭 바(`bg-surface-tab`, 활성 탭 `bg-surface text-ink`). 모바일은 드롭다운으로 접거나 가로 스크롤 칩으로 바꾼다.
- **로딩**: 0.4초 이상이면 실제 레이아웃과 같은 모양의 스켈레톤(`bg-sand-light animate-pulse`). 스피너만 띄우지 않는다.
- **실패·빈 화면**: 공용 컴포넌트 하나로. 제목(무슨 일인지) + 설명(어떻게 하면 되는지) + 주 행동 버튼 1개. 참고: `src/app/(main)/error.tsx`.
- **성공 피드백**: 화면 이동이 없으면 토스트(아래쪽, 3초, 해요체 한 문장).
- **바텀시트**: 모바일에서 선택지 고르기·확인에 사용. `rounded-t-sheet`. 데스크톱에서는 가운데 대화상자로 바꾼다.
- **애니메이션**: 200~300ms, 의미 있는 전환에만. `prefers-reduced-motion` 을 존중한다 (전역 적용).

## 7. UX 라이팅

- **해요체**로 쓴다 ("완료됐어요", "다시 시도해 주세요"). 명령형·딱딱한 공문체·영어 약어는 피한다.
- 짧게: 제목 한 줄, 설명 두 줄 이내.
- 버튼은 무엇이 일어나는지 동사로 ("확인" 대신 "예약하기").
- 오류는 **무슨 일이 생겼고 어떻게 하면 되는지**를 쓴다. 사용자를 탓하지 않는다 ("잘못 입력하셨습니다" ✗ → "휴대폰 번호 11자리를 입력해 주세요" ○).
- 같은 대상은 어디서나 같은 단어로 부른다.

## 8. 접근성

- 대비 AA(본문 4.5:1), 포커스 링 유지(`:focus-visible` 전역 적용), 키보드로 모든 기능 사용 가능.
- 아이콘만 있는 버튼은 `aria-label`. 이미지는 의미 있으면 `alt`, 장식이면 `alt=""`.
- 색만으로 상태를 구분하지 않는다 (아이콘·문구 함께).
- 시맨틱 태그(`header`, `nav`, `main`, `section`, `button`)를 쓴다. 클릭되는 `div` 금지.

## 9. 브랜드 자산

- 현대자동차 로고·차량 사진·전용 서체는 **공모전 측이 제공했거나 사용을 허용한 것만** 쓴다. 출처가 불분명한 이미지는 쓰지 않는다.
- 현대자동차 공식 사이트를 그대로 베끼지 않는다. 색·비율만 인용하고 화면 구성은 우리 서비스 목적에 맞게 설계한다.
