# MOBI.AI 디자인 규칙

현대자동차 공모전 프로젝트이고, 화면은 **차량 디스플레이(Pleos Connect, 가로형)** 에서 보인다. 아래 기준을 합쳐 우리만의 규칙으로 쓴다. 기준끼리 숫자가 다르면 더 엄격한 쪽을 쓴다.

| 영역 | 기준 | 출처 |
| --- | --- | --- |
| 색·모양 | 마이현대 앱 | 마이현대 앱 화면(밝은 파랑 강조, 둥근 흰 카드, 연한 그림자, 아이콘 원 + 라벨 + 값 행)을 차량 가로 화면에 맞게 옮긴 UX Pilot 시안 (2026-11-10, 사용자 결정). 시안: https://uxpilot.ai/a/ui-design?page=sUlReQmV7AI4Du6DX4YH |
| 크기(터치·글자·간격) | 차량 디스플레이 | Android for Cars 설계 지침 (Design for Driving, docs.partner.android.com/drivingux) |
| 창·반응 속도·앱 아이콘·주간/야간 | Pleos Connect UI 디자인 가이드 | Pleos 개발자 문서 UI 디자인 가이드와 Design Resources(Figma) (1-1장) |
| UX 행동·화면 구성·문구 | 토스식 원칙 | 「토스에서 찾아본 10가지 UX 법칙」(모비인사이드 재게시, 2023) — 외부 기획자의 관찰 글이며 토스 공식 가이드가 아니다 |
| 주행 중 제약 | 안전 | 이 프로젝트 규칙 + Android Automotive 주행 중 UX 제한 |
| 공모전 | **디자인 규정 없음** | 공모전 사이트(appdevchallenge.auto-hmg.io) 접수·심사·FAQ·유의사항 확인 (2026-11-10). 심사 항목 중 차량특화성("주행·정차 맥락 및 차량 기능과 유기적으로 결합")과 기술 활용성("핵심 기능과 사용 경험에 적절히 활용")이 디자인과 관련된다. 2차 PT 심사 기준은 아직 공개되지 않았다 |

**토큰은 `src/shared/ui/theme.ts` 에 있다.** 컴포넌트에서 색·크기를 직접 정하지 말고 토큰(`colors.*`, `typography.*`, `spacing.*`, `sizes.*`, `radius.*`, `layout.*`)만 쓴다. 이 파일 밖의 임의 색상(`"#..."`, `"rgb(...)"`)은 ESLint 에러다.
공용 컴포넌트(`src/shared/ui/`): `AppText`, `Button`, `TextField`, `Screen`, `Columns`, `StatusView`, `Card`·`SummaryCard`, `InfoRow`, `IconBadge`, `ChipGroup`·`ToggleChip`, `ConfirmDialog`. 새 화면은 이것부터 쓴다. 색은 주간·야간 두 세트라 `themedStyles`·`useColors` 로 읽는다 (1-3장).

## 1. 차량 화면 크기와 배치

1. **터치 대상은 최소 76×76dp** (`sizes.touchTarget`), 주 버튼 높이 88dp (`sizes.primaryButton`). 터치 대상 사이는 최소 24dp (`spacing.md`).
2. **글자는 주요 정보 32dp 이상, 보조 정보 24dp 이상.** `typography.caption`(24)보다 작게 쓰지 않는다.
3. 화면은 가로로 넓다. 본문은 `Screen` 의 폭 제한(`layout.content` 1440, 한 작업 화면은 `width="narrow"` 880) 안에 가운데 정렬하고 좌우 여백은 `layout.gutter`(48). 넓은 창(`layout.twoColumnWidth` 1000dp 이상)에서는 `Columns` 로 2단(왼쪽 40%: 요약·그림, 오른쪽 60%: 목록·선택지)으로 나누고, 좁은 창에서는 위아래로 쌓는다.
4. 고정 크기 대신 `flex`·`flexWrap`·`gap` 으로 배치해 해상도가 달라도 깨지지 않게 한다. 가로 스크롤이 생기면 안 된다. 여러 해상도를 확인할 때는 `useWindowDimensions` 로 분기한다.
5. 주 행동은 `Screen` 의 `footer`(하단 고정)에 둔다. 운전자가 화면 아래쪽을 손으로 찾기 쉽다.
6. 안전 영역과 뒤로 가기는 `Screen` 이 처리한다 (네이티브 헤더는 끈다: 안전 영역 여백이 두 번 들어간다). 첫 화면은 `back={false}`. 화면 루트에서 직접 여백을 계산하지 않는다.
7. 폭이 `layout.compactWidth`(720dp) 미만인 창(1:1 분할 세로 창, 휴대폰 확인용)에서는 `Screen` 이 좌우 여백을 `gutterCompact`(24)로 줄이고 하단 버튼을 폭에 맞춰 세로로 쌓는다. 그래서 `footer` 에는 보조 버튼을 먼저, 주 CTA 를 마지막에 둔다 (좁은 창에서 주 CTA 가 맨 아래). 글자 크기는 줄이지 않는다. 컴포넌트에서 분기가 필요하면 `useCompact()`.
8. 입력칸의 단위는 라벨에 붙인다("키 (cm)"). 설명이 필요한 안내만 `hint` 로 라벨 아래에 둔다.
9. 시스템 글자 크기 설정을 막지 않는다 (`allowFontScaling={false}` 금지).

## 1-1. Pleos Connect UI 디자인 가이드 기준

- 앱 창은 화면에 1개 또는 2개(1:1, 2:1)로 뜨고 사용자가 가로·세로를 바꿀 수 있다. `screenOrientation` 을 지정하지 않으면 세로(portrait) 창 하나로 실행된다. **가로·세로 레이아웃을 모두 지원**한다.
- 대비 4.5:1 이상, 정보는 1~2초 안에 읽히게, **입력 후 응답 0.25초 이내(넘으면 처리 중 표시)**, 한 손 조작. 반응 속도 규칙은 3장 "0.25초 안에 반응".
- 글자: 최소 12sp·실제 높이 18px 이상(Pleos), 우리 토큰은 더 큰 Android for Cars 기준(24dp 이상)을 쓴다. 한 줄 80자 이하, 문단 3줄 이하.
- 화면 안 아이콘은 48×48dp 그리드, 글자 라벨과 함께. 앱 아이콘은 1-2장.
- 주간·야간 밝기·대비 자동 조정을 권장한다 → 1-3장.
- **Design Resources(Figma) 대조**: 정확한 컴포넌트 치수는 문서에 이미지로만 있어 Figma 를 기준으로 한다. 새 컴포넌트를 만들거나 모양을 바꿀 때는 Figma 의 같은 종류(버튼, 목록 행, 대화상자, 입력칸)와 모양·배치를 비교해 Pleos 기본 앱들과 어색하지 않게 맞춘다. 치수가 다르면 더 큰 쪽을 쓴다 (보통 우리 토큰). 기존 화면은 아직 대조하지 않았다 (`docs/todo.md`).

## 1-2. 앱 아이콘·스플래시

- `assets/images/` 의 아이콘·스플래시는 BodyFit AI 전용이다 (2026-11-10 교체): 밝은 파랑(`colors.primary`) 바탕에 흰 운전석 옆모습과 옅은 파란 호. Higgsfield(GPT Image)로 만든 그림을 토큰 색으로 다시 칠해 다섯 파일로 나눴다. 스플래시는 흰 배경에 올라가므로 시트를 파랑으로 칠했다.
- 파일과 크기 (`app.config.ts` 가 참조한다. 파일 이름을 바꾸면 설정도 함께 고친다):

| 파일 | 크기 | 용도 |
| --- | --- | --- |
| `icon.png` | 1024×1024 | 기본 앱 아이콘 |
| `android-icon-foreground.png` | 512×512, 투명 배경 | Adaptive Icon 전경. 모양은 가운데 지름 약 61%(108dp 중 66dp) 원 안에 둔다. 바깥은 기기 마스크에 잘린다 |
| `android-icon-background.png` | 512×512 | Adaptive Icon 배경. 단색이나 단순한 면 |
| `android-icon-monochrome.png` | 432×432, 투명 배경 | 단색 테마 아이콘 (전경과 같은 모양을 한 색으로) |
| `splash-icon.png` | 투명 배경 | 시작 화면 가운데 이미지 |

- 앱 마켓 등록용 아이콘은 별도로 512×512 PNG/JPEG, 1MB 이하 (Pleos).
- 모양은 작은 크기(48dp)에서도 알아보는 단순한 형태 하나. 아이콘 안에 글자를 넣지 않는다.
- 색은 `colors` 토큰 값에서 고른다. 현대·기아·제네시스·Pleos 로고나 엠블럼은 넣지 않는다 (10장).
- `android/` 는 생성물이라 아이콘을 바꾼 뒤에는 prebuild 로 다시 만들어야 앱에 반영된다.

## 1-3. 주간·야간

- 앱은 시스템 색 모드를 따라 주간·야간 색 세트를 자동으로 바꾼다 (`app.config.ts` 의 `userInterfaceStyle: "automatic"`, 2026-11-12 도입). Android Automotive 는 차량의 주간·야간 상태를 시스템 다크 모드로 넘겨준다. 사용자가 직접 고르는 설정은 없다.
- 색 세트는 `theme.ts` 의 `palettes.day`·`palettes.night` 다. 토큰 이름은 같고 값만 다르다. **색을 모듈 최상위에서 고정해 쓰지 않는다** (`colors` 를 직접 import 할 수 없다). `src/shared/ui/use-theme.ts` 로 읽는다:

  ```tsx
  const useStyles = themedStyles((colors) => ({
    box: { backgroundColor: colors.surface, borderRadius: radius.card },
  }));

  export function Box() {
    const styles = useStyles(); // 차량이 주간·야간을 바꾸면 다시 렌더된다
    const colors = useColors(); // 스타일 밖에서 색이 필요할 때만 (ActivityIndicator, placeholder)
    ...
  }
  ```

- 야간 색 원칙:
  - 넓은 밝은 면을 쓰지 않는다 (운전자 눈부심). 화면 바탕 `surfaceMuted` #0E1116, 카드 `surface` #1A1F27, 칩 `fill` #2A313C. 글자 `ink` 는 순백이 아닌 #E6E9EE.
  - 강조·상태 색(`primary` #5C9DFF, `success` #57C785, `danger` #F28B82, `warning` #E5A94B)은 어두운 면 위 글자로도 4.5:1 이 나오게 밝은 톤으로 바뀐다. 그래서 그 면 위 글자 `onPrimary` 는 야간에 어두운 색(#0B1220)이다. **색 면 위 글자는 `colors.surface` 가 아니라 `onPrimary`(`AppText tone="inverse"`)를 쓴다.**
  - 확인 창 뒤를 가리는 막은 `scrim` 토큰.
- 색을 바꾸거나 새 조합(글자색·바탕색)을 쓰면 `src/shared/ui/theme.test.ts` 의 조합 목록에 넣는다. 두 세트 모두 4.5:1 이상인지 테스트가 검사한다.
- 앱이 뜨기 전의 색은 `app.config.ts` 가 맡는다: 창 바탕(`backgroundColor` + `values-night` 의 `activityBackground`), 시작 화면(`expo-splash-screen` 의 `dark`). 값은 `surfaceMuted` 의 주간·야간 값과 같게 둔다. 바꾸면 prebuild 로 다시 만들어야 반영된다.
- 이미지·아이콘은 투명 배경 PNG 로 넣는다. 흰 배경을 이미지에 박아 넣지 않는다. 운전석 그림(밝은 회색 시트)은 야간 카드 위에서도 그대로 쓴다.
- Pleos 에뮬레이터에서 주간·야간 전환 확인은 아직 하지 못했다 (`docs/todo.md`).

## 2. 주행 중 제약 (안전)

- **주행 중에는 화면 조작을 요구하지 않는다.** 이 앱의 화면은 주차 중 사용을 전제로 한다. Android Automotive 는 주행 중 일반 앱 화면을 가린다.
- 주행 중 필요한 안내는 **음성(TTS)** 으로 하고, 확인이 필요한 조작은 "차를 세운 뒤 화면에서 확인해 주세요"로 미룬다.
- 차량을 움직이는 버튼(시트 맞추기 등)은 기어 P 가 아니면 비활성화하고, 왜 안 되는지 문구로 알려 준다.
- 차량이 움직이는 동안 **멈추기** 버튼을 항상 보여 준다.
- 한눈에 읽히게: 화면당 핵심 정보는 짧게, 문장보다 숫자·단어로.

## 3. 토스식 UX 원칙 → 우리 규칙

| 원칙 | 우리 규칙 |
| --- | --- |
| **익숙함** | 헤더·뒤로가기·하단 CTA 위치는 일반적인 앱 관례를 따른다. 새로운 조작 방식을 발명하지 않는다. |
| **한 화면에 한 가지** | 한 화면은 하나의 목적만 가진다. **주 CTA는 화면당 1개** (`Button` 기본 variant). 나머지는 `variant="secondary"`. |
| **선택지는 적게, 목적별로 묶기** | 같은 목적의 요소를 한 섹션으로 묶고 섹션 제목을 단다. 차량 화면에서는 한 화면 선택지를 더 적게. |
| **덩어리로 보여주기** | 한 섹션의 항목은 7개 이하. 숫자는 끊어 읽게 표시한다. |
| **입력은 적게, 받을 때는 너그럽게** | 꼭 필요한 정보만 묻는다. "175cm", "175.5" 처럼 형식이 섞여도 받는다 (`parseMeasurement`). 선택 입력은 비워도 동작해야 한다. |
| **복잡함은 서비스가 떠안기** | 사용자가 고르기 전에 추론할 수 있으면 미리 계산해 추천한다 (예: 체형으로 시트 자세 추천, 앉은키를 모르면 키로 추정). |
| **마지막 인상이 기억된다** | 실패·빈 화면은 `StatusView` 하나로 통일한다. 탓하지 않는 해요체 문구 + 바로 할 수 있는 다음 행동 1개. 같은 실패는 어디서나 같은 문구(`*-error-copy.ts`). |
| **보기 좋으면 쓰기 쉽다고 느낀다** | 넉넉한 여백, 정돈된 정렬, 적은 색 수. 장식보다 여백으로 구분한다. |
| **강조는 드물게** | 강조색(`highlight`)·배지·애니메이션은 화면당 한 곳에만. |
| **0.25초 안에 반응** | 모든 조작은 즉시 눈에 보이는 반응을 준다 (눌림 상태). 0.25초 안에 끝나지 않을 수 있는 작업은 처리 중 표시를 한다: 화면 데이터는 실제 모양의 스켈레톤(`colors.surfaceMuted` 블록), 버튼 작업은 `loading`. 토스 사례는 0.4초지만 Pleos UI 가이드(0.25초)가 더 엄격해 이 값을 쓴다. |

- 위 표는 주간 값이다. 야간 값과 원칙은 1-3장.

## 5. 타이포그래피 (`typography.`)

| 토큰 | 크기 | 용도 |
| --- | --- | --- |
| `display` | 48 | 첫 화면 대표 문구 (화면당 1개) |
| `title` | 40 | 화면 제목 (`Screen` 의 title) |
| `heading` | 36 | 섹션 제목 |
| `body` / `bodyStrong` | 32 | 주요 본문 / 강조·버튼 글자 |
| `secondary` | 28 | 보조 본문, 입력 라벨 |

- 글꼴은 시스템 기본(한국어는 기기 기본 한글 글꼴)을 쓴다. 현대 전용 서체(Hyundai Sans)는 공모전 측이 제공·허용한 경우에만 쓴다.
- 한 화면에 굵기 3단계 이하.
- 글자는 항상 `AppText` 로 쓴다 (`variant`, `tone`).

## 6. 모서리·간격·그림자

- 마이현대 앱처럼 크게 둥글린다: 카드 `radius.card`(24), 버튼·입력칸·선택 타일 `radius.control`(20), 칩·아이콘 원·개수 표시 `radius.pill`.
- 그림자는 카드에만 `shadows.card`(아주 연한 그림자) 하나를 쓴다. 다른 그림자를 만들지 않는다.
- 간격은 `spacing` 토큰(8 배수). 카드 사이는 `spacing.md`(24), 화면 제목과 본문 사이는 `spacing.lg`(32).

## 7. 컴포넌트 규칙

- **주 CTA**: `<Button label="..." />` (primary). 동사형 문구("맞추기", "등록하기"). 처리 중에는 `loading` 으로 중복 입력을 막는다.
- **보조 버튼**: `variant="secondary"` (흰 면 + 옅은 테두리). 주 CTA보다 눈에 띄면 안 된다.
- **차량을 움직이는 버튼**: 누르면 `ConfirmDialog` 로 확인 → 확인 후 실행. 실행 중에는 같은 자리에 "멈추기". 시스템 `Alert` 는 글자·버튼이 차량 기준보다 작아 쓰지 않는다.
- **입력**: `TextField` (라벨은 위, placeholder 로 라벨 대신 금지). 오류는 입력칸 아래에 이유와 고치는 방법을 함께. 숫자는 `keyboardType="decimal-pad"`.
- **목록**: 행 높이 최소 `sizes.touchTarget` + 여백. 섹션당 7개 이하.
- **카드**: `Card` (흰 면 + 연한 그림자, 제목·개수 표시·구분선·› 포함). 화면 바탕은 `Screen` 이 옅은 회색으로 깐다.
- **요약 카드**: `SummaryCard` (파란 면에 라벨 + 값 + ›). 화면에서 가장 중요한 한 줄에만, 화면당 1개.
- **2단 구성**: `Columns` (왼쪽: 요약 카드·그림, 오른쪽: 목록·선택지).
- **정보 행**: `InfoRow` (아이콘 원 `IconBadge` + 라벨 + 값 + 보조 설명). 아이콘은 뜻을 혼자 전하지 않고 항상 글자와 함께 쓴다.
- **고르기**: 하나만 고르면 `ChipGroup`, 여러 개면 `ToggleChip`(격자에 놓을 때는 `shape="tile"`). 고른 칩은 색과 ✓ 를 함께 표시한다.
- **그림**: 운전석 그림은 `bodyfit-seat-image.tsx` (`assets/images/seat.png`, 투명 배경). 꾸밈용이므로 자세 값은 옆의 숫자·글자로 함께 전한다.
- **로딩**: 0.25초 안에 끝나지 않을 수 있으면 실제 레이아웃과 같은 모양의 스켈레톤. 스피너만 띄우지 않는다 (버튼 안 `loading` 은 예외).
- **실패·빈 화면**: `StatusView` (제목 + 설명 + 주 행동 1개).
- **성공 피드백**: 화면 이동이 없으면 화면 문구 한 줄(해요체) + 필요하면 음성 안내(`speakQuietly`).
- **애니메이션**: 200~300ms, 의미 있는 전환에만. 주행 중 시선을 끄는 움직임은 쓰지 않는다.

## 8. UX 라이팅

- **해요체**로 쓴다 ("맞췄어요", "다시 시도해 주세요"). 명령형·딱딱한 공문체·영어 약어는 피한다.
- 짧게: 제목 한 줄, 설명 두 줄 이내. 음성 안내는 한 문장.
- 버튼은 무엇이 일어나는지 동사로 ("확인" 대신 "맞추기").
- 오류는 **무슨 일이 생겼고 어떻게 하면 되는지**를 쓴다. 사용자를 탓하지 않는다 ("잘못 입력하셨습니다" ✗ → "키는 120~220cm 사이로 입력해 주세요" ○).
- 같은 대상은 어디서나 같은 단어로 부른다 (운전자, 시트, 등받이, 앞뒤 위치, 좌판 기울기).

## 9. 접근성

- 대비 AA(본문 4.5:1).
- 누르는 요소는 `accessibilityRole="button"` + `accessibilityLabel`. 상태는 `accessibilityState`(disabled, busy).
- 바뀌는 안내 문구는 `accessibilityLiveRegion="polite"`.
- **색만으로 상태를 구분하지 않는다** (예: 시트 막대에 "지금 45% → 추천 52%" 숫자를 함께).
- 제목은 `accessibilityRole="header"`.

## 10. 브랜드 자산

- 현대·기아·제네시스·Pleos 로고, 차량 사진, 전용 서체는 **공모전 측이 제공했거나 사용을 허용한 것만** 쓴다. 공모전 사이트에는 로고·상표 사용 규정이 없으므로 지금은 쓰지 않는다. 출처가 불분명한 이미지는 쓰지 않는다.
- 마이현대 앱의 모양(색 느낌, 카드, 칩, 행)은 참고하되 화면·문구·그림을 그대로 베끼지 않는다. 화면 구성은 우리 서비스 목적에 맞게 설계한다.
- 운전석 그림(`assets/images/seat.png`)과 앱 아이콘은 Higgsfield 로 만들었다 (실제 차량 사진·로고 아님). Higgsfield 이용약관(2026-10-23 개정) 4.4조는 Output 의 소유권을 회사가 주장하지 않고 상업적 이용을 제한하지 않는다고 적고 있다 (2026-11-10 확인). 약관은 Output 의 유일성을 보장하지 않으며, 법이 요구하면 AI 생성물임을 밝혀야 한다.
- 공모전 유의사항: 출품작은 제3자의 권리(초상권, 저작권, 디자인권 등)를 침해하지 않아야 한다. 외부 아이콘·이미지·폰트·효과음은 상업적 이용이 가능한 라이선스인지 확인하고, 넣는 커밋 메시지에 출처와 라이선스를 적는다.
