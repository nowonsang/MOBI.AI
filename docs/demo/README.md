# 시연 영상 자료 (화면 + 설명)

기획서의 "시연" 부분을 영상으로 만들 때 쓰는 자료다. 2026-11-14 에 Pleos Connect 에뮬레이터(v2.1.0, contest 빌드)에서 실제 앱을 돌려 찍었다.

- 그림: `shots/` (2560×1440 PNG, 번호 순서가 영상 순서)
- 화면 속 이름·체형은 모두 예시다 (DriverA·DriverB·DriverC). 실명·계정 정보는 없다.
- 그림을 다시 찍을 때: 에뮬레이터에서 앱을 띄우고 `adb exec-out screencap -p > 파일.png`

## 영상에 꼭 넣을 안내 (자막 또는 내레이션)

실제와 다르게 보일 수 있는 부분이다. 빼면 2차 PT 에서 실제 앱과 비교될 때 문제가 된다.

| 장면                | 넣을 안내                                                                                                   |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| 8·9·10 (시트 이동)  | "에뮬레이터에는 시트 모터가 없어 '시연 모드'로 진행 화면만 보여 줍니다. 실제 차량에서는 시트가 움직입니다." |
| 4·5 (카메라로 재기) | "에뮬레이터 카메라는 고정 사진이라 예시 자세로 보여 줍니다."                                                |
| 16·17 (주행 자세)   | "에뮬레이터에서는 예시 기록으로 보여 줍니다." (화면에도 '시연용 예시 기록이에요' 표시가 있다)               |

## 기획서 시나리오와의 대응

기획서 4번 "주요 사용 시나리오"의 번호다.

| 기획서 시나리오                                | 쓰는 장면                              |
| ---------------------------------------------- | -------------------------------------- |
| 1-① 처음 타서 등록 → 추천 자세로 조절 → 출발   | 1 → 2 → 3 → (4·5) → 6 → 7 → 8 → 9 → 15 |
| 1-② 다른 사람이 타면 "○○님이시죠?" · 장거리    | 20 → 11                                |
| 1-③ 긴 운전 뒤 "자세가 앞으로 쏠렸어요" → 반영 | 16 → 17 → 18 → 19                      |
| 1-④ 평소 쓰던 열선·온도로                      | 13 → 14                                |
| 2 QR 코드로 다른 차에 옮기기                   | 21 (내보내는 쪽만)                     |

## 찍지 못한 것

- 실제 시트가 움직이는 모습, 실제 얼굴로 한 카메라 측정·주행 자세 관찰: 에뮬레이터에 없다. 실차 영상이 생기면 8·9·4·17 을 바꾼다.
- 음성으로 묻고 답하는 흐름: 에뮬레이터에서 음성 인식이 동작하지 않아 화면 흐름만 찍었다.
- QR 가져오기(읽는 쪽): 에뮬레이터 카메라로 코드를 비출 수 없어 내보내기 화면만 찍었다.
- "반영 전후 비교" 화면: 반영 뒤 한 번 더 주행한 기록이 있어야 나온다. 이번에는 찍지 않았다.

## 시연 영상 만들기

`docs/demo/video/` 의 스크립트가 위 화면 그림과 대사를 영상(1920×1080)으로 합친다. 결과 영상은 저장소에 넣지 않는다.

- 올린 곳: 시연 영상 https://youtu.be/TH8B7vasBSM, 릴리스 APK https://github.com/nowonsang/MOBI.AI/releases/tag/v0.1.1

```bash
cd docs/demo/video && python3 build.py <결과.mp4>          # 긴 판 (가로 1920×1080)
cd docs/demo/video && python3 build_shorts.py <결과.mp4>   # 광고형 숏폼 (세로 1080×1920, 약 56초)
```

| 파일 | 내용 |
| --- | --- |
| `build.py` | 장면 그림(Pillow) + 대사 음성 → ffmpeg 로 합친다. 필요한 것: macOS, ffmpeg, Python Pillow |
| `scenes.py` | 장면과 대사 (29장면, 약 6분 18초). 기획서 1~6번 순서 |
| `voice/NN.mp3` | 장면 번호별 대사 음성. 없는 장면은 macOS 음성(Yuna)으로 읽는다 |
| `art/*.png` | 기획 배경 장면의 삽화 4장 |
| `build_shorts.py` | 세로형 광고형 숏폼. `build.py` 의 색·글꼴·합치는 방법을 그대로 쓰고, 장면을 바로 넘기며 천천히 확대한다. 화면 캡처는 앱 창 부분만 잘라 쓴다 |
| `scenes_short.py`, `voice-short/` | 숏폼의 장면과 대사 (11장면), 대사 음성. 흐름: 자세는 무너진다 → 맞추기 → 지켜보기 → 알려주기 → 배우기 → 다음 추천. 핵심은 "주행 중 흐트러진 자세를 학습해 다음 추천에 반영" |

- 대사를 고치면 그 장면의 `voice/NN.mp3` 도 다시 만든다 (장면을 넣거나 빼면 번호가 밀린다).
- 삽화는 Higgsfield(GPT Image), 대사 음성은 Higgsfield 의 ElevenLabs 음성(프리셋 "Mark")으로 만들었다. 실제 사람·차량 사진·로고가 아니다 (출처·약관은 `ui-design` 스킬 10장).
